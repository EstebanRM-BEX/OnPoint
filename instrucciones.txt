Guía de migración a Clean Architecture — WMS App

  Estructura de carpetas a crear

  lib/features/<modulo>/
  ├── domain/
  │   ├── entities/          # Clases puras, sin fromMap ni dependencias
  │   ├── repositories/      # Abstract class con Either<Failure, T>
  │   └── usecases/          # Un archivo por usecase
  ├── data/
  │   ├── models/            # XModel extends Entity + fromMap + fromLegacy/toLegacy
  │   ├── datasources/       # remote e local (interfaces + impls)
  │   └── repositories/      # XRepositoryImpl @LazySingleton
  └── presentation/
      ├── bloc/              # _event, _state, _bloc
      ├── pages/             # Pantallas
      └── widgets/           # Widgets propios del módulo

  Entities

  Usecases

  @lazySingleton
  class GetProductosLocal implements UseCase<List<ProductoInventario>, NoParams> {
    final InventarioRepository repository;
    GetProductosLocal(this.repository);

    @override
    Future<Either<Failure, List<ProductoInventario>>> call(NoParams params) =>
        repository.getProductosLocal();
  }

  Fase 2 — Data

  Models

  class ProductoInventarioModel extends ProductoInventario {
    const ProductoInventarioModel({super.productId, super.name});

    factory ProductoInventarioModel.fromMap(Map<String, dynamic> json) =>
        ProductoInventarioModel(
          productId: json['product_id'],
          name: json['name'],
        );

    // Puente con tipos legacy (solo dentro de data/)
    factory ProductoInventarioModel.fromLegacy(Product legacy) =>
        ProductoInventarioModel(productId: legacy.productId, name: legacy.name);

    Product toLegacy() => Product(productId: productId, name: name);

  Local datasource

  - Inyecta DataBaseSqlite (ya registrado en injection_container.dart)
  - Usa .fromLegacy() al leer de DB y .toLegacy() al escribir
  - Future.wait([...]) para inserts paralelos

  Repository impl

  @LazySingleton(as: InventarioRepository)
  class InventarioRepositoryImpl implements InventarioRepository {
    @override
    Future<Either<Failure, List<ProductoInventario>>> getProductosLocal() async {
      try {
        final result = await localDataSource.getProductos();
        return Right(result.cast<ProductoInventario>());  // ← IMPORTANTE el .cast()
      } on CacheException catch (e) {
        return Left(CacheFailure(e.message));
      }
    }
  }

  ▎ Regla crítica: Siempre .cast<Entidad>() al retornar listas de modelos. Sin esto, Dart conserva el tipo concreto en runtime y firstWhere falla con _TypeError.

  Verificar: dart run build_runner build → registrado en injection_container.config.dart

  Flags de color de campos (patrón doble-condición)

  // En el bloc, dos booleans por campo:
  bool locationIsOk = false;   // verde/amarillo cuando true
  bool isLocationOk = true;    // false → rojo; true → gris/verde

  // En clenanFields():
  locationIsOk = false;
  isLocationOk = true;   // ← siempre true al limpiar, NUNCA false

  Patrón sesión expirada

  result.fold(
    (failure) {
      if (failure is SessionExpiredFailure) emit(SessionExpiredState());
      emit(FailureState(failure.message));
    },
    (data) => emit(SuccessState(data)),
  );

  Transformers (bloc_concurrency)

  on<BusquedaEvent>(_handler, transformer: droppable());
  on<GetListadoEvent>(_handler, transformer: restartable());

  clenanFields() — checklist completo

  void clenanFields() {
    // 1. Flags visuales → false
    xIsOk = false;
    // 2. Flags de validación → true (para color gris, no rojo)
    isXOk = true;
    // 3. Objetos seleccionados → null
    currentItem = null;
    // 4. Contadores → 0
    quantitySelected = 0;
    // 5. Controllers → clear (TODOS, incluyendo cantidadController)
    controller.clear();
    cantidadController.clear();
    // 6. Listas → clear
    lista.clear();
    // 7. Flags boolean → reset
    viewQuantity = false;
  }
